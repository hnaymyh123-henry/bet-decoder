# Bet Decoder → Trading Decision Agent · 改造 PRD

> **一句话**：把 Bet Decoder 从"**诊断** bet 隐含什么"升级为"基于诊断**做出交易决策并在模拟盘执行**"的 agent。
>
> **版本**：v0.1（草案，未 LOCK）· 2026-07-03
> **状态**：产品方向已定（决策引擎 + Paper trading），本文档定义功能形态，待用户拍板 §8 后走 `/dev` Phase 1 冻结。
> **前置阅读**：`BET_DECODER_VISION.md`（Bet Card 原语）· `PRD.md`（现产品 v1.0）。本文档是它们之上的**决策层**，不推翻任何现有模块。

---

## 0. 为什么做这次改造

### 0.1 现状：站在决策悬崖，却刻意留白

现有系统是一条**纯诊断链**：`股价/组合 → 反解隐含假设 → xray 判断层 → Bet Card`。它回答"**市场隐含相信什么 + 证据多强**"，从不回答"**那我该做什么**"。

关键事实：决策所需的零件已造好大半，最后一步被**亲手掐断**了——`intelligence.py` 的 `_kelly` 算出了风险回报的形状，注释却写着 "deliberately NOT a position size … does not recommend or size a trade"。所以本次改造**不是从零造交易大脑**，而是接上这条留白的最后一步，并且接得和现在一样诚实。

### 0.2 改造后的一句话定位

> **一个逼你保持诚实的交易决策 agent**：替你量化市场共识、把它对撞成一个明确的行动（买/持/避/空 + 仓位 + 止损）、在模拟盘自动执行并跟踪盈亏，且每个决策都自带认错条件。

### 0.3 用户心智变更

| | 旧（Bet Decoder v1.0） | 新（Decision Agent） |
|---|---|---|
| 用户来做什么 | "X 光透视这个 bet 隐含什么" | "让 agent 告诉我该拿它怎么办，并替我在模拟盘上试" |
| 核心产物 | Bet Card（诊断） | **Trade Thesis**（决策）+ 模拟持仓 |
| 结束状态 | 看懂了 | 有了带止损的仓位 + 一条可复盘的记录 |

## 1. 核心概念升级：从 Bet Card 到 Trade Thesis

### 1.1 两个原语，正交互补

- **Bet Card**（已有）答 **What**：市场/某方隐含相信什么。
- **Trade Thesis**（新增）答 **So What**：基于这个诊断，我该做什么、做多少、什么时候认错。

一张 Trade Thesis **挂在**一张 Bet Card 上（决策必须可溯源到它诊断的那个 bet）。Bet Card 不可变快照的性质被继承——一次决策就是一条冻结记录。

### 1.2 决策的第一性公式

> **决策 =（你的 view − 市场隐含 view）× 信心 × 风险容量 + 退出纪律**

这个系统的独特优势：它已经把**市场隐含 view 量化出来了**（隐含 CAGR / 隐含倍数 / 情景概率）。交易决策缺的只是另一半——一个**独立的 view**，以及把两者的差转成行动。四个因子分别对应下面的 stance / conviction / 仓位 / KILL。

### 1.3 Trade Thesis 标准结构

```
┌─ Trade Thesis ─────────────────────────────────┐
│ Subject:      NVDA @ $214.86 (Market)            │
│ Decodes:      Bet Card #abc（市场隐含 ~38% CAGR）│
│ ──────────────────────────────────────────────  │
│ Stance:       AVOID  （方向判定）                 │
│ Conviction:   LOW    （信心）                     │
│ Edge:         市场隐含 38% vs 可辩护上限 ~25%      │
│               → 高估、无安全边际                   │
│ ──────────────────────────────────────────────  │
│ Position:     目标权重 0%（不建仓）               │
│               [若 short：¼Kelly→6%，单仓上限内]   │
│ Entry:        —                                   │
│ Invalidation: 实际营收增速连续 2 季跌破大盘中位     │
│   (KILL)       ~11%（隐含要 38%）→ 论点破          │
│ Horizon:      5y（DCF 视角）                       │
│ ──────────────────────────────────────────────  │
│ Rationale:    一句话，带 base-rate 外部视角        │
│ Self-falsify: "我若错，会从哪个信号先知道"          │
└──────────────────────────────────────────────────┘
```

| 字段 | 含义 | 来源（复用现有诊断） |
|---|---|---|
| stance | 方向：strong_buy / accumulate / hold / trim / avoid / short | `undervalued` flag · `above_top` · 情景概率 |
| conviction | 信心：high / medium / low | base_rate 罕见度 + 证据强度 |
| edge | 你的 view 与市场隐含的差（可量化） | 隐含数字 vs 可辩护区间 |
| position | 目标权重 % + 建仓/加/减逻辑 | Kelly（`_kelly` 的 p_win/上行/下行） |
| invalidation | KILL line，可证伪的认错条件 | `wwhtbt` 的 KILL 项 |
| horizon | 时间视角 | DCF 5y，按 stance 调整 |
| rationale | 一句话理由 | `verdict_zh` 风格 |
| self_falsification | 明确写出"错了怎么知道" | 本层新增，强制字段 |

## 2. 决策规则（产品行为规范）

> 以下是**产品级规则**，定义 agent 的判断行为，不是代码。默认参数标注"[默认]"，最终值见 §8 待决议。

### 2.1 stance 判定

| 诊断信号 | stance |
|---|---|
| DCF 基础业务价值 > 现价（`undervalued`） | accumulate / strong_buy |
| 现价落在可辩护情景区间内 + 证据支持 | hold（已持有）/ 小仓 accumulate |
| 隐含数字在 base-rate 顶部尾（仅极少数同行达到过） | avoid（降 conviction） |
| 现价高于所有情景估值（`above_top`，纯叙事） | avoid，或 short（若开启做空） |
| 风险回报不对称且下行 > 上行（`unfavorable`） | avoid / trim |

### 2.2 conviction 判定

- **high**：隐含数字不极端（base-rate 中段）+ 证据支持 + 情景概率不拥挤在尾部。
- **medium**：上述任一项存疑。
- **low**：隐含数字在极端尾部 / 证据 honest-empty / DCF 无解（纯叙事）。

### 2.3 仓位规则

1. 由 `_kelly` 的 p_win、上行、下行算原始 Kelly 分数 `f*`。
2. 取 **¼ Kelly**（fractional，防过度下注）[默认]。
3. 再按 conviction 打折：high ×1.0 / medium ×0.6 / low ×0.3。
4. **单仓上限 20%**、**账户现金下限 10%** [默认]。
5. conviction=low 且 edge 小 → 目标权重可为 0（不硬凑交易，见 §2.5）。

### 2.4 止损 / 认错（KILL line）

- 每张 Thesis 必带一条来自 `wwhtbt` 的 KILL line（可证伪、绑定 base-rate 中位）。
- 模拟盘每次重估时检查 KILL 是否触发；触发 → thesis 标记 `invalidated` + 触发平仓建议/动作（见 §3.4）。

### 2.5 什么时候不交易（诚实约束，护城河）

- conviction=low **且** edge 未超过阈值 → 默认 **hold / 空仓**，明确输出"不值得下注"而非硬造一个买卖。
- 证据 honest-empty（provider 无法联网核实）→ 不得据此提升 conviction，理由里注明"未经网络验证"。
- **每张 Thesis 强制填 `self_falsification`**——没有认错条件的决策不允许生成。这是本产品区别于黑箱喊单的根本。

## 3. 模拟盘（Paper Trading）

### 3.1 账户模型（产品定义）

- **账户**：初始虚拟资金（默认 $100,000）、当前现金、当前净值。
- **持仓**：每个 ticker 的数量、平均成本、开仓日、绑定的 thesis。
- **流水**：每一笔模拟成交（时间、方向、数量、价格、理由、thesis）。
- 单一模拟账户即可（MVP 不做多账户/多策略隔离）。

### 3.2 自动执行流程

`Trade Thesis 出 stance + 目标权重 → 按现价 + 账户净值换算成数量 → 下模拟单 → 更新现金/持仓/流水`。stance=avoid/hold 且已空仓 → 不动作，仅留记录。

### 3.3 P&L 与重估

- 持仓按最新价 mark-to-market，展示浮动盈亏 + 账户净值曲线。
- MVP **手动触发重估**（用户点"刷新"），自动定时监控留到 §7 后续阶段。

### 3.4 KILL 触发行为

重估时若某持仓的 thesis KILL 条件成立：标记该 thesis `invalidated`、在账户面板高亮告警、生成"平仓"建议。**是否自动平仓 = 待决议 D4**（默认：告警 + 建议，不自动平，保留人可见的认错时刻）。

## 4. 产品形态 / 界面变更

沿用现有三区工作台（`app.html`），**新增而非重做**：

- **T·卡片决策层**：每张 Bet Card 下方新增"决策"区块——展示 Trade Thesis（stance / conviction / edge / 仓位 / KILL），一个"让 agent 决策"按钮。
- **T·模拟盘面板**：新增账户视图——现金、持仓表（含浮盈、绑定 thesis、KILL 状态）、净值曲线、成交流水。
- **T·决策 activity 流**：复用现有 SSE，流出 agent 的决策推理过程（"读市场隐含→形成独立 view→算 edge→定仓位→写 KILL"），和现有 decode 流一致。

设计仍严守 `pricelens_design_system.md`（无蓝紫渐变、数字右对齐 mono、表格优先）。stance/盈亏用现有 oxblood accent 配给，绿涨红跌需符合设计系统的克制用色。

## 6. 用户旅程（决策版 demo）

1. 用户粘贴 `NVDA` → 得到 Bet Card（市场隐含 ~38% CAGR，已有）。
2. 点"让 agent 决策" → SSE 流出推理 → 得到 Trade Thesis：**AVOID / LOW / 隐含 38% 远超可辩护 25% / 目标 0% / KILL：增速连 2 季跌破 11%**。
3. 换 `COST`（温和 compounder）→ Thesis：**accumulate / medium / 目标权重 8%（¼Kelly×medium，上限内）**。
4. 点"执行" → 模拟盘按 8% 建 COST 仓，现金扣减，流水 +1。
5. 账户面板：持仓 COST（浮盈/亏 + KILL 状态）、净值曲线、$100k 起。
6. 隔日重估：若 COST 增速跌破 KILL → thesis 标 invalidated + 告警"该认错了"。

**Wow 点**：不是"荐股 target $X"，而是**每个决策都摆出它自己的证伪条件**，且模拟盘真的替你把纪律执行下去。

## 7. 诚实边界与产品原则

1. **不硬凑交易**：低信心/小 edge → 明说"不值得下注"。
2. **决策自带认错条件**：`self_falsification` 是强制字段。
3. **不碰真钱**：本版止步 Paper trading；实盘（T14）需每单人工 approve，且 AI 助手不代为下单。
4. **不做个性化投顾话术**：输出的是"市场隐含 vs 可辩护区间"的结构化对撞 + 概率/base-rate，不是"你应该买"的劝导。
5. **外部视角优先**：base_rate 永远在场，压制过度自信。

## 10. 成功标准

- 任一已 decode 的卡都能一键得到**带止损的**结构化决策，`self_falsification` 覆盖率 100%。
- 模拟盘能完整跑通"决策→建仓→重估→KILL 告警"闭环。
- 低信心场景下 agent **明确拒绝下注**（不制造假交易）——可用一组反例验证。
- 决策全程可通过 activity 流看到推理，无黑箱。
